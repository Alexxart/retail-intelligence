# Складская модель — этап 2
Синтетический кейс. Seed 2026 для склада, seed 42 для продаж. Продажи сохранены: модель условна на наблюдаемых выполненных заказах. Ежедневный ledger (gzip CSV) — SKU × склад × день; inventory.csv — месячный агрегат. Продажи списываются в день заказа, возвраты поступают по return_day; все возвраты считаются пригодными к продаже. Январские возвраты 2026 входят в финансовые когорты, но не в складской период. Начальный запас 5 или 25 единиц, целевой запас зависит от экспоненциально сглаженных продаж и сезонности. Плановые заказы поступают через 7/14 дней, незавершённый pipeline на конец периода не считается запасом. Срочное поступление покрывает нехватку для наблюдаемых продаж; дополнительный спрос моделируется Пуассоном и при нехватке теряется, не входит в выручку. Это условная симуляция, не прогноз потерь или оптимизация закупок. Стоимость срочного пополнения не моделируется.

Баланс: stock_start + receipts + emergency_receipts + restocked - sales = stock_end. ordered — размещённые плановые заказы; lead_days — срок; stockout — индикатор нулевого конечного запаса, срочного пополнения или неудовлетворённого спроса; stockout_days — сумма индикаторов, не часы отсутствия. stock_unit_days — сумма ежедневных конечных остатков. unmet_demand — дополнительный неудовлетворённый спрос. Средняя стоимость запасов = сумма stock_unit_days × стандартная себестоимость года / календарные дни года. COGS — финансовая когорта заказа, за вычетом возвратов, поэтому оборот является приближением, не бухгалтерским оборотом по датам движения. Turnover = COGS / средний запас; DIO = дни года / turnover. Stockout rate = дни дефицита / SKU-склад-дни. Unmet rate = unmet / (sales + unmet). ABC — годовая чистая выручка, накопленная доля до SKU 80/95%; XYZ — коэффициент вариации месячных проданных единиц (12 месяцев, включая нули, population std), X ≤ .25, Y ≤ .5, Z иначе. Нулевой спрос относится к Z. Сезонность влияет на CV, это не оценка ошибки прогноза.

Результаты: inventory_annual.csv, inventory_summary.csv, abc_xyz.csv. Запуск generate.py → analyze.py → factors.py → build.py → dashboard.py. Дневной ledger не импортируется в SQL на данном этапе; месячная таблица импортируется. Финансовые показатели неизменны, так как коммерческие события не изменены.
